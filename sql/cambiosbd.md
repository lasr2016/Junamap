# Registro de Cambios en Base de Datos: `cambiosbd.md`

Este documento detalla las modificaciones realizadas en el esquema de la base de datos para la tabla `public.locales`.

---

## 1. Cambio de Tipo de Dato para Horarios (`abre` y `cierra`)

### ¿Qué se cambió?
- **Anterior:** Se utilizaba `NUMERIC(4,2)` para representar las horas en formato decimal (ej: `8.5` para las 08:30 y `21.0` para las 21:00).
- **Nuevo:** Se migró al tipo nativo **`TIME`** de PostgreSQL (ej: `'08:30:00'` o `'21:00:00'`).

### ¿Por qué se hizo el cambio?
1. **Claridad y Semántica:** Es mucho más legible almacenar `'08:30'` que descifrar números con decimales.
2. **Validación:** PostgreSQL valida automáticamente que no se ingresen valores fuera del rango horario válido (00:00:00 a 23:59:59).
3. **Compatibilidad:** Se alinea directamente con los campos HTML `<input type="time">` que se usan en los formularios (como el modal *"Registrar mi local"*).

---

## 2. Comandos SQL

### Opción A: Aplicar el cambio a una tabla existente en Supabase (Sin perder datos)
Si ya tienes la tabla creada (del archivo locales.sql) y con datos en Supabase, ejecuta esta consulta en el **SQL Editor** para convertir las columnas existentes automáticamente:

```sql
-- Convertir las columnas 'abre' y 'cierra' de NUMERIC a TIME
ALTER TABLE public.locales 
    ALTER COLUMN abre TYPE TIME 
        USING (make_time(floor(abre)::int, round((abre % 1) * 60)::int, 0)),
    ALTER COLUMN cierra TYPE TIME 
        USING (make_time(floor(cierra)::int, round((cierra % 1) * 60)::int, 0));
```

---

### Opción B: Crear la tabla desde cero (Estructura nueva)
Si prefieres recrear la tabla completa, la definición ahora queda así:

```sql
CREATE TABLE IF NOT EXISTS public.locales (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nombre VARCHAR(150) NOT NULL,
    tipo VARCHAR(50) NOT NULL,
    direccion TEXT NOT NULL,
    lat DOUBLE PRECISION NOT NULL,
    lng DOUBLE PRECISION NOT NULL,
    abre TIME,                                   -- Antes: NUMERIC(4,2)
    cierra TIME,                                 -- Antes: NUMERIC(4,2)
    telefono VARCHAR(30),
    descripcion TEXT,
    verificado BOOLEAN DEFAULT FALSE,
    metodo_cobro VARCHAR(100) DEFAULT 'Edenred POS',
    productos TEXT[] DEFAULT '{}',
    activo BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 3. Impacto en el Frontend (`src/App.jsx`)
En el archivo `src/App.jsx`, se actualizaron las funciones auxiliares de hora:
- **`fmt(h)`:** Ahora detecta strings `'HH:MM:SS'` y extrae `'HH:MM'` directamente para la vista.
- **`isLocalOpen(l)`:** Se agregó la función `toMinutes()` para comparar con exactitud los minutos actuales frente al rango `abre` y `cierra`.
- Se mantuvo compatibilidad hacia atrás por si en algún momento se reciben datos numéricos antiguos.
